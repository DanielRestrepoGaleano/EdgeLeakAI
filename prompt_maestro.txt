## ROL Y CONTEXTO

Actúa como Ingeniero Senior de Software Embebido y Especialista en QA para
sistemas IoT críticos. El proyecto EdgeLeak AI detecta microfugas en
lavaplatos domésticos combinando un ESP32 (sensores YF-S201 + KY-037)
con una app Flutter (Dart 3.x) y análisis contextual en la nube (Groq API
/ Llama 3.3 70B), siguiendo la arquitectura Edge-to-Cloud.

En esta versión (v3.0), la detección acústica de goteo se migra
completamente al hardware Edge. El ESP32 envía ahora un tercer campo
"picos" (int) en su payload JSON, representando los micro-picos acústicos
contados en el intervalo de 5 segundos. Flutter ya no mide ruido absoluto;
en cambio, acumula y clasifica estos picos para decidir si invocar a Groq.

### 1.1  Firmware ESP32 (C++ / Arduino)
Archivo: C:\Users\danie\OneDrive\Escritorio\edgeleak\esp32_firmware.txt
Versión: v3.0 (Pattern AI)

Nuevo payload JSON enviado por POST /api/sensor cada 5 s:
  { "ruido": <int 0-4095>, "flujo": <float L/min>, "picos": <int ≥ 0> }

Lógica clave en el ESP32:
  - promedioSilencio: promedio móvil exponencial (α = 0.001) del ADC
    cuando el sensor está bajo el umbral → línea base dinámica.
  - UMBRAL_SENSIBILIDAD: 150 ADC sobre la línea base para contar un pico.
  - DEBOUNCE_GOTEO: 200 ms mínimo entre picos válidos.
  - picosDetectados: contador acumulado en 5 s → se envía y reinicia.

### 1.2  Servicios Flutter (lib/)
Leer directorio: C:\Users\danie\OneDrive\Escritorio\edgeleak\lib\

Servicios clave existentes (NO borrar):
  - RuidoFilterService: filtro ventana deslizante (12 muestras / 60 s).
      · ResultadoRuido: { silencio, impactoAislado, patronGoteo }
      · Umbral de ruido significativo: 1 500 ADC.
      · Umbral de silencio base: 800 ADC.
      · Patrón confirmado: ≥ 3 muestras sobre umbral en la ventana.
  - BaselineService: perfil estadístico adaptativo de 5 días.
      · Período diurno: 06:00-22:00 / nocturno: 22:00-06:00.
      · Requiere ≥ 30 lecturas; si insuficientes → conservador (true).
      · esDesviacionSignificativa(): ΔFlujo > 0.30 L/min ó ΔRuido > 500 ADC.
  - GroqApiService: invocación event-driven (no polling).
  - EmailService: alerta SMTP por severidad.
  - DatabaseService: SQLite v5 (lecturas_raw, lecturas_resumen_5d,
    historial_mensual, historial, usuarios).
  - LocalApiService: servidor HTTP local puerto 8080, auth x-api-key.

Máquina de estados (EstadoSensor — jerarquía estricta):
  1. Fuga     → flujo > 5.0 L/min (invocación directa a Groq, sin esperar strikes)
  2. Anomalía → flujo ∈ (0.5, 5.0] L/min  ó  patronGoteo ó  lógica nocturna
  3. Normal   → default

Lógica nocturna (hora 0:00-6:00):
  flujo == 0.0  +  promedio ruido > 800 ADC  +  ≥ 3 muestras en ventana
  → ResultadoRuido.patronGoteo → EstadoSensor.Anomalía

Regla de strikes (sin cambio):
  3 lecturas consecutivas Anomalía + esDesviacionSignificativa() == true
  → invocar Groq API.
